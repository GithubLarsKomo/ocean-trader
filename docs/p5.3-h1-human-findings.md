# P5.3-H1 — First Human-Test Findings

**Source:** physical iPhone Safari human test of the P5.3 acceptance candidate
**Status:** fix candidate

## Observed blockers

1. Rudder command showed `STBD 35°` while both visual rudder representations pointed to the opposite side.
2. A loaded harbour page began moving laterally before the tester deliberately resumed control.
3. The observed campaign attempt had existing damage (`HULL 89%`), confirming that the page was restoring an in-progress persisted manoeuvre rather than starting a clean training state.

## Root-cause / design decision

- P5.3 uses positive helm = STBD and negative helm = PORT in physics. CSS screen rotation and Babylon scene rotation require opposite mathematical transforms to represent that same bridge convention. Presentation is now centralized in `rudder-presentation.ts`.
- Persistence must retain position, motion, damage and helm state for H-12, but a restored browser page should not continue integrating wind/current/inertia before the tester regains control. Every page load therefore starts with physics paused. The first engine, rudder or bow-thruster command arms the simulation.
- RESET also returns to the paused state. Campaign RESET still retains accumulated condition damage and collision count.

## Re-test gate

Before H-01…H-13 continue:

- `STBD 35°` must point starboard in the HUD/indicator and the vessel rudder;
- `PORT 35°` must point port in both;
- MID must center both;
- fresh and restored pages must remain spatially frozen until the first manoeuvring command;
- restored campaign damage/state must remain intact;
- after the first manoeuvring command, the configured wind/current must act normally.
