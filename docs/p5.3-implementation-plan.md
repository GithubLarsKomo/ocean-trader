# P5.3 — Harbour Manoeuvring Core Implementation Plan

**Status:** active
**Integration branch:** `feat/p5.3-harbour-manoeuvring-core`
**Baseline:** `main` at `16d284d`
**Working rule:** each slice is implemented on a child branch and merged into the P5.3 integration branch only after its automated gate is green.

## Goal

Move the harbour simulator from a playable technical prototype to a low-speed manoeuvring core in which the player must anticipate inertia, residual motion and the delayed effect of bridge commands.

The renderer remains non-authoritative. Campaign settlement remains outside the simulation core. Existing 2D harbour behaviour remains the production fallback until P5.3 human usability is accepted.

## Delivery sequence

`P5.3-A Propulsion → P5.3-B Hull/Rudder → P5.3-C Prop Walk/Thruster → P5.3-D Calibration → P5.3-E Environment → P5.3-F Berthing`

## P5.3-B — Hull Dynamics & Rudder Force

**Branch:** `feat/p5.3b-hull-rudder`
**Base:** accepted P5.3-A integration head

### Scope

- split hull forces into surge, sway and yaw terms
- add linear + quadratic surge drag
- add linear + quadratic sway damping
- add linear + quadratic yaw damping
- add sway/yaw coupling
- replace direct rudder yaw moment with a rudder lateral force + lever arm
- derive rudder inflow from STW plus propeller wash
- preserve residual yaw after MIDSHIPS/STOP
- allow short engine kicks to create low-speed steering authority

## P5.3-D — Vessel & Load Calibration

**Branch:** `feat/p5.3d-vessel-calibration`
**Base:** accepted P5.3-C integration head

### Scope

Calibrate Handysize first, then make other vessel classes relative to the accepted reference behaviour.

Required distinctions:

- Coaster: agile, short response and stopping distance
- Handysize: reference low-speed handling
- Feeder: higher windage and lateral sensitivity
- Panamax: high inertia, long stopping distance and slow yaw response

Load state must measurably affect acceleration, stopping and turn response.

### Files

- `src/simulation/vessel-parameters.ts`
- `src/simulation/benchmarks.ts`
- `src/simulation/benchmarks.test.ts`
- `docs/p5.3-calibration-evidence.md` (new)

### Gate

- AT-07 class distinction
- AT-08 load distinction
- target: normalized Panamax stopping distance >= 1.8 × Coaster
- benchmark evidence recorded in repository

## Final P5.3 integration gate

P5.3 may merge to `main` only when:

1. all ten acceptance tests are automated and green;
2. CI and build are green;
3. Handysize low-speed response is accepted by human play test;
4. Alongside Berthing, Unberthing and Turning Basin are playable;
5. P6 campaign integration and persistence remain intact;
6. the legacy 2D harbour remains available as fallback;
7. physical-phone usability is accepted.

The final product question is:

> Does the player have to think ahead about the ship's future motion?

If late corrective inputs can still make a large ship stop, rotate and berth almost immediately, P5.3 is not complete.
